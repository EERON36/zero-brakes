# CLAUDE.md: Zero Brakes

This file gives Claude Code the context it needs in every session. Read `docs/PLAN.md` for the full game plan.

## What this is
**Zero Brakes** is a one-thumb, landscape, side-view arcade game for **iPhone and iPad only**. A WCMX-style daredevil in a sports wheelchair with side rocket pods jumps oncoming traffic, pulls stunts and chases a high score. Runs last 30 s to 3 min.

## About the developer
- A solo developer with a little game-making experience from years ago. **Explain technical choices in plain language.** Keep steps small and concrete.
- The budget is close to zero: prefer free tools and Apple frameworks.
- Playtests with a best friend who uses a wheelchair. Hero, chair, crash visuals and all game text go past him (`needs-friend-review` label).
- The repo was set up on Windows (M0). **All code is written and built on the Mac.**

## Tech stack
- Swift (**Swift 5 language mode**), **SpriteKit** for gameplay, **SwiftUI** app shell and menus. Minimum **iOS 17**.
- Project generated by **XcodeGen** from `project.yml`. **Never hand-edit `.xcodeproj`.** It's gitignored. Run `xcodegen generate` after adding or removing files or changing settings.
- Tests: XCTest in `ZeroBrakesTests/`. Game logic (physics, spawner, scoring) is plain Swift and must be testable without SpriteKit.

## Commands (on the Mac)
```bash
xcodegen generate                                   # (re)create ZeroBrakes.xcodeproj
xcodebuild -scheme ZeroBrakes -destination 'platform=iOS Simulator,name=iPhone 16' build
xcodebuild -scheme ZeroBrakes -destination 'platform=iOS Simulator,name=iPhone 16' test
xcrun simctl io booted screenshot /tmp/zb.png       # screenshot the running simulator
```
Adjust the simulator name to one that exists (`xcrun simctl list devices available`).

## Non-negotiable rules
1. **All gameplay numbers live in `ZeroBrakes/Game/Tuning.swift`**, each with a plain-English comment. No magic numbers elsewhere. Keep `docs/tuning.md` in sync.
2. **The code never depends on final art or audio.** All art loads through `ArtLibrary` using keys from `ArtManifest`. A missing PNG falls back to a placeholder shape at the exact manifest size and anchor. A missing sound plays nothing. Swapping in real art means dropping a PNG into the right folder, with no code change.
3. `docs/asset-manifest.md` and `ArtManifest.swift` must agree (keys, sizes, anchors, frames).
4. **Logic is separate from visuals.** Nodes display state; they don't own the rules.
5. **Delta-time based updates** so 60 Hz and 120 Hz play the same.
6. The in-game tuning panel shows only in Debug and TestFlight builds (StoreKit `AppTransaction.environment`), never in App Store builds.
7. **Scope discipline:** don't build ads, purchases, store or meta features before their milestone (ads and IAP = M4). Fun first.
8. **Tone:** badass, skilled, stylish. Never joke about disability. The chair is a WCMX sports chair, never a hospital chair. **Never use "NOS" or Fast & Furious references.** Use "nitro", "boost" and "rockets".

## Art pipeline
- Art is made in Astra (an external AI design tool) from GitHub issues labeled `art`, `animation`, `ui`, `fx`, `audio`, `concept`.
- Style: `docs/art-style.md`. Sizes: `docs/asset-manifest.md`. Issue template: `.github/ISSUE_TEMPLATE/art-asset.md`.
- Masters arrive at @3x. `tools/make_2x.sh` (uses `sips`) generates @2x. `tools/check_assets.sh` validates sizes. Both scripts are still to be written in M1.
- **Only create art issues for the current milestone.**
- `.gitkeep` files in `Resources/Art/*.atlas/` hold the folders in git. Exclude them from the bundle in `project.yml` (or delete them once real PNGs arrive) so the atlas compiler doesn't complain.
