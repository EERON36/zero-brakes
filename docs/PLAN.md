# Zero Brakes: Game Plan

## Context

You want to build **Zero Brakes**, a one-thumb arcade game for iPhone and iPad. A daredevil in a WCMX-style sports wheelchair with side-mounted rockets jumps over oncoming traffic, pulls stunts and chases a high score. Runs last 30 seconds to 3 minutes. The tone is badass and stylish. The fun comes from the stunts, never from the disability.

Decisions so far:
- **You own a Mac.** We set up the repo, docs and art issues from this Windows PC. You then clone onto the Mac and write all the game code there with Claude Code.
- **Side view, landscape.**
- **Public GitHub repo** (account `EERON36`).
- **Working title: Zero Brakes.**
- The folder `C:\Projects\zero_brakes` is empty and not yet a git repo. `git`, `gh` (logged in with `repo` + `workflow` scopes) and Node are installed.

This file is the plan. It becomes `docs/PLAN.md` in the repo. Approved on 2026-09-29. M0 (repo, docs, art issues) was set up from Windows; M1 onward is built on the Mac.

## 1. Tech stack: Swift + SpriteKit

**Recommendation:** Swift, Apple's SpriteKit 2D engine, a SwiftUI app shell for menus, and Xcode on your Mac. Everything here is free.

In plain language:
- **SpriteKit is Apple's own 2D game engine and ships with Xcode.** There's nothing to install or license, and it runs well on every iPhone and iPad.
- **Apple features are built in.** Haptics (vibration), Game Center leaderboards, in-app purchases (StoreKit 2), screen-clip recording (ReplayKit) and TestFlight all work without third-party plugins. With Unity or Godot, each of these means extra plugins, and each plugin can break.
- **It works well with Claude Code.** A SpriteKit project is just text files. Unity keeps most of a game inside scene files and editor clicks, which Claude can't easily see or change. On your Mac, Claude Code can build the project, run tests and take simulator screenshots itself.
- **It's iOS-only, and so is your game.** You lose nothing by skipping a cross-platform engine.
- **Trade-off:** Apple isn't adding many new features to SpriteKit. It's stable and mature, and it's more than enough for a 2D arcade game.

Project details:
- **Minimum iOS:** iOS 17. That covers nearly all active devices in 2026 and lets us use modern SwiftUI.
- **Project file:** Generated by **XcodeGen** (free, one `brew install`) from a readable `project.yml`. Xcode's own project file is a huge, fragile text file that's easy to corrupt. This way Claude never hand-edits it.
- **Swift language mode:** Swift 5. This avoids Swift 6's strict concurrency warnings, which would only confuse at this stage.
- **Before your paid account arrives:** Xcode's free "Personal Team" lets you install the game on your own iPhone by cable. These installs expire after 7 days, and you just press Run again. Once the paid account is active, builds go out through TestFlight.

## 2. Game design

### Screen and camera
- Landscape (both directions). Side view, the hero faces right, traffic comes from the right.
- The hero stays at a fixed spot about **25% from the left edge**, and the world scrolls past. That leaves about 75% of the screen as warning space.
- **Design-safe area of 844 × 390 world units.** Wider phones show more road ahead. iPads (4:3) show more sky and ground. Gameplay is identical on every device.
- The road surface sits at a fixed height near the bottom. The sky and a parallax city (layers that scroll at different speeds) fill the rest.

### Controls: one thumb, the whole screen is the button
| Action | Input | Notes |
|---|---|---|
| Jump | Touch down anywhere | Fires on touch-*down*, so there's no lag |
| Higher jump | Keep holding | Letting go early cuts the jump short (variable jump height) |
| Rockets | Keep holding after the jump's peak | In the air: extra lift and forward push, which means longer jumps. Uses nitro. |
| Ground boost | Hold as you land | Rockets keep firing on the road, giving you extra speed and score |
| Tricks (M2) | Swipe while airborne | Swipe up for a backflip, down for a frontflip. You must land level. |

This is the **One-Touch** control scheme. For testing, M1 also includes a second scheme, **Split**: tap anywhere to jump and hold a thumb-sized button in the bottom-right to boost. You can switch between them in the tuning panel and keep whichever feels better. Later there's a left-handed option, which mirrors the button side.

### Physics feel (custom-coded, not a physics simulation, so it stays predictable and tunable)
- **Snappy arc.** Gravity is stronger on the way down than on the way up. Jumps feel punchy instead of floaty.
- **Forgiveness:**
  - **Coyote time** (about 0.08 s): you can still jump just after the moment you should have.
  - **Jump buffer** (about 0.12 s): a tap just before landing jumps as soon as you touch down.
- **Landing:**
  - A small squash, a dust puff and a light haptic tap.
  - In M2, landing at an angle greater than the landing tolerance (about 25°) counts as a *sloppy landing*. You lose your combo but don't crash.
- **Roofs are safe.** Landing on top of a vehicle is fine, and you ride its roof until it passes. Only hitting the *front or side* of a vehicle is a crash. This keeps crashes feeling fair.
- **Hitboxes** are slightly smaller than the sprites. Near-misses should feel like near-misses, not unfair crashes.

### Obstacles (introduced gradually)
| Vehicle / hazard | Size | How to beat it | Milestone |
|---|---|---|---|
| Compact car | Short, low | Any jump | M1 |
| Van | Taller | Full jump | M1 |
| Motorbike | Small, fast | Timing | M2 |
| Box truck | Tall | Full jump + rockets, or land on the roof | M2 |
| City bus | Long | Rockets, or roof-ride it | M2 |
| Traffic cones / barrier | Static, low | Hop | M2 |
| Launch ramp | Helpful | Big-air bonus | M2 |
| Semi-truck + trailer | Very long | Roof chain | M3 |

### Difficulty ramp
- **Speed** rises smoothly over the run (for example 300 → 650 units/s over about 90 s, then levels off).
- **Spacing:** gaps between vehicles shrink over time, and the mix shifts toward bigger vehicles.
- **Patterns (M2).** Hand-designed short sequences, like "car-car-truck" or "bus then bike", are grouped into difficulty tiers. The game strings patterns together and adds **rest beats** so there's rhythm, not random noise.
- **Fairness guarantee.** Before placing a vehicle, the spawner calculates the hero's maximum jump reach at the current speed. It never creates an impossible gap. Unit tests check this.

### Scoring
- **Distance** gives steady points.
- **Clearing a vehicle** gives points by vehicle size.
- **Near-miss** (M2): clearing a vehicle by a hair earns a bonus.
- **Stunts and combos** (M2):
  - Trick points pile up while you're in the air. A clean landing **banks** them.
  - Each consecutive clean stunt within about 2 s raises the **combo multiplier** (×2, ×3…).
  - A sloppy landing drops the multiplier. A crash loses whatever hasn't been banked.
- **Stunt ideas:**
  - Backflip and Frontflip (backflips are the signature WCMX move)
  - Double Flip
  - Big Air (height)
  - Long Haul (clearing 2+ vehicles in one jump)
  - Roof Ride (landing on a vehicle)
  - Thread the Needle (between two tall vehicles)
  - Skim (a very low clear)
  - Rocket Manual (ground boost on the rear wheels)
- **Nitro economy (M2).** Stunts and near-misses refill nitro. Risky play gives you more boost, and more boost gives you bigger scores. That's the core "hard to master" loop. In M1, nitro just refills slowly on its own.

### Crash
- A short slow-motion hit, sparks, camera shake and a heavy haptic. The hero and chair tumble *together*, like a pro wiping out at a competition. It's never slapstick and never leaves him looking helpless.
- The **results screen appears within 1 s**, with **Retry as the biggest button**. Fast restarts are what make "one more go" happen.
- **Continue (M4):** once per run, by watching a rewarded ad. You respawn with a brief shield.

### Power-ups (M3, spawn as pickups on the road or in the air)
- **Magnet:** pulls coins to you.
- **Roll Cage:** absorbs one crash.
- **Nitro Can:** instantly refills the nitro tank.
- **Mega Rockets:** about 4 s of auto-flight above traffic.
- **2× Coins:** doubles coins for a short time.

### Accessibility
These are planned from the start. Your friend's first playtest may reveal more:
- One-Touch scheme, adjustable hold sensitivity, left-handed mirroring
- Toggles for screen shake, flashing effects and haptics
- Text scaling in menus
- Hazard colors that can be told apart by shape and outline, not color alone

## 3. Progression and economy (M3)

- **One currency: coins.** They're earned only by playing: pickups plus a share of your score. **Coins are never sold for real money.** That keeps the game from being pay-to-win.
- **Earning rate:** a typical run earns about 50–300 coins. A good player earns about 1,000 coins in 10 minutes.
- **Cosmetics (earned with coins):** you can use most items within the first hour of play, and the best-looking items take about 1–2 weeks of casual play.

| Category | Examples | Coin price |
|---|---|---|
| Chair frame paint | Matte black, candy red, carbon fibre, chrome, flame decals | 500 / 1,500 / 4,000 |
| Wheels | Spoke styles, colored push rims, glowing rims | 500–3,000 |
| Rocket flame color | Blue, green, purple, gold, rainbow | 800–5,000 |
| Outfit | Helmets, jackets, gloves, pads | 500–3,000 |
| Trail effects | Sparks, neon streak | 2,000+ |

- **Milestone unlocks** are free rewards for reaching score goals ("Reach 10,000 → Gold flame"). This gives skilled players something to chase that money can't buy.
- **Upgrades** (5 levels each, costs 200 / 500 / 1,000 / 2,000 / 4,000):
  - Bigger nitro tank
  - Faster nitro recharge
  - Longer power-up duration
  - Coin magnet range

  Each level gives about +10%. That's noticeable, but not enough to make leaderboards meaningless.
- **Missions** give coin rewards. There are 3 active at a time, such as "Land 3 backflips in one run" or "Roof-ride a bus".
- **Hero customization:** skin tone, hair, helmet and outfit are separate layers, so he can be customized without redrawing the whole character.

## 4. Monetization (M4, only after the core is fun)

| Item | Recommendation |
|---|---|
| **Ad network** | **Google AdMob**: free, the most common choice, with an official Swift package. It includes Google's **UMP** consent form, which is required for Europe and the UK. |
| **Rewarded ads** | Always optional. **Continue** (once per run) and **Double coins** on the results screen. |
| **Interstitials** | These are the full-screen ads between runs. Show at most one after every 4th run, at least 4 minutes apart, never in the first 3 runs of a new player, and never right after a rewarded ad. They could be skipped entirely at launch and tested later. |
| **Remove Ads** | A one-time non-consumable purchase, about $2.99–$3.99. It removes interstitials. Rewarded ads stay as an optional choice, clearly explained. |
| **Cosmetic IAPs** | Non-consumable bundles, about $0.99–$2.99 each (e.g. "Neon Pack", "Chrome Pack"). They're cosmetic only. |
| **Purchases code** | Apple's **StoreKit 2**, which is free and needs no server or RevenueCat. A **Restore Purchases** button is required. |

### App Store requirements this triggers
- **App Tracking Transparency (ATT):**
  - AdMob uses the advertising ID, so the game must show Apple's tracking prompt with a clear reason (`NSUserTrackingUsageDescription`).
  - Show it *after* the first run, with a short friendly pre-screen, not on the very first launch.
  - Declining still gives non-personalized ads.
- **Info.plist:** AdMob's list of SKAdNetwork IDs.
- **Privacy manifest** (`PrivacyInfo.xcprivacy`):
  - Declare that the game uses UserDefaults to save data.
  - Google's SDK brings its own manifest.
- **Privacy "nutrition" labels** in App Store Connect. With AdMob you declare:
  - Identifiers (device ID)
  - Usage data (advertising data, product interaction)
  - Diagnostics
  - "Data used to track you" (if ATT is allowed)
- **Age rating:**
  - Answer Apple's updated age-rating questionnaire honestly.
  - Stylized crashes probably count as infrequent or mild cartoon violence, which likely means a **9+**-type rating.
  - **Don't** put it in the Kids category. Kids apps can't use third-party ad tracking.
- **Paid Apps Agreement:** tax and banking forms in App Store Connect. IAPs don't work until this is done.
- **EU trader status:**
  - To sell or show ads in the EU, you must declare whether you're a "trader".
  - If you are, your **address, phone number and email are shown publicly** on the EU App Store page.
  - Decide this consciously. Some solo developers use a P.O. box or business address.
- **Apple Small Business Program:**
  - Cuts Apple's commission from 30% to **15%** if you earn under $1M a year.
  - Apply right after your developer account is active, before you sell anything.

### Honest earnings estimate
- The only real required cost is Apple's **$99 a year**.
- **Typical result:** a small, well-made, un-marketed indie arcade game gets **a few hundred to a few thousand downloads in year one**.
- **Rough per-player earnings:** light ads earn about $0.05–$0.30 per player. About 1–2% of players buy a $3 item.
- **Realistic year-one range:**
  - **$0–$100** with no promotion at all
  - **$100–$1,000** with some TikTok/Reels clips and good word of mouth
  - More only if a clip goes viral or Apple features it
- A good first goal is **covering the $99 fee and building a portfolio piece**. Anything beyond that is a bonus.

## 6. Art style and asset list

### Art style (summary; the full version becomes `docs/art-style.md`)
- **Look:** bold action-sports sticker art.
  - Clean vector-style cartoon with **thick dark outlines**.
  - Flat colors with one shadow tone and one highlight tone (cel-shaded).
  - Street-art energy in the backgrounds.
- **Setting:** a city at **dusk** with neon. The dark background makes rocket flames and the hero pop.
- **Palette:**

  | Name | Hex | Used for |
  |---|---|---|
  | Outline | `#14121A` | All outlines |
  | Asphalt | `#2A2A36` | Road |
  | Midnight | `#1B1F3B` | Night sky, far background |
  | Dusk purple | `#5B3A8C` | Sky, buildings |
  | Sunset orange | `#FF7A2F` | Sky glow, accents |
  | Hot magenta | `#FF3D7F` | Accents |
  | Nitro cyan | `#2EE6FF` | Nitro and rocket effects |
  | Hazard yellow | `#FFD23F` | Hazards |
  | Chrome | `#C9D1D9` | Metal parts |
  | Off-white | `#F4F1EA` | Highlights, text |

  Traffic uses **muted, desaturated** colors so the hero always stands out.
- **Camera:**
  - Pure side view (profile). The hero faces right, traffic faces left.
  - Light comes from the top-left.
- **Showing the camber:** the title and menu art uses a 3/4 hero shot that shows the angled wheels clearly. In gameplay, the far wheel peeks out at an angle.
- **Outlines** (in pixels at @3x):
  - Hero and vehicles: 9 px (3 pt)
  - Mid background: 6 px (2 pt)
  - Far background: no outline, to create depth
- **Hero proportions:**
  - Heroic and athletic: broad shoulders, strong arms, a slightly large head for readability.
  - Seated height about 2.5 heads.
  - Helmet, gloves and knee/elbow pads.
- **The chair: a real WCMX / sports chair.**
  - Rigid low frame and **low backrest**
  - **Strongly cambered rear wheels**
  - **Push rims**
  - Small front casters
  - Rear suspension shocks
  - A rear grind bar / anti-tip bar
  - A lap strap
  - Two **rocket pods mounted on the sides**
  - Nothing that looks medical: no tall back, no push handles, no hospital grey.
- **File rules:**
  - PNG-32 with transparent background, sRGB.
  - **Use the exact canvas size.** Don't trim or crop the transparent edges.
  - `lowercase_snake_case` names, frames numbered `_01`, `_02`…
  - Suffixes `@2x` / `@3x`.
- **@2x workflow:**
  - Astra delivers the **@3x master** only.
  - A free script (`tools/make_2x.sh`, using the Mac's built-in `sips`) makes the @2x copies.
  - A second script (`tools/check_assets.sh`) checks every file's size against the manifest.

### How art drops in without code changes
- **One source of truth.** `docs/asset-manifest.md` and a matching `ArtManifest.swift` list every asset: key, size in points, anchor point, frame count and hitbox.
- **Automatic placeholders.** The game asks `ArtLibrary` for an asset by key. If no PNG exists, it draws a colored placeholder shape at exactly the right size and anchor.
- **Swapping art = adding or replacing a PNG** in the right folder. No code changes.
- **Layered hero rig.**
  - The hero is built from **layers that share one canvas**: chair frame, spinning wheels, rider, helmet and rocket pods.
  - The code spins the wheels and moves the layers, so we need **very few frame-by-frame animations**. AI art tools struggle to keep animation frames consistent, so this matters.
  - It also makes customization simple: every skin or outfit is just a different layer PNG.
- **Recolorable rocket flames.** Flames are drawn in white-hot and grayscale and tinted in code. One set of flame frames supports every unlockable flame color.

### Key architecture rules
These rules also go into `CLAUDE.md`, so every future session follows them.
1. **All gameplay numbers live in `Tuning.swift`.** That includes jump height, gravity, speed, the ramp, spawn gaps, nitro and hitbox insets. Every value gets a plain-English comment. No "magic numbers" anywhere else.
2. **In-game tuning panel.**
   - Triple-tap the top-left corner to open live sliders for the key values.
   - The panel also has a control-scheme switch, a "Reset", and a **"Copy values"** button that copies Swift code ready to paste back into `Tuning.swift`.
   - It's available in Xcode and **TestFlight** builds and hidden in App Store builds. TestFlight is detected automatically (StoreKit's `AppTransaction.environment`).
   - Tuning sessions happen live on the device.
3. **Code never needs final art to run.** Art is only ever loaded through `ArtLibrary`, and sounds only through `Audio`. Missing files fall back to a placeholder shape or silence.
4. **Game logic is separate from the visuals.** Physics, spawning and scoring are plain Swift that tests can run without a screen. SpriteKit nodes only *display* the state.
5. **Timing is based on elapsed time (delta time).** The game plays the same at 60 Hz and 120 Hz (ProMotion).

### M1: Smallest playable prototype, run on your own iPhone
**Goal:** answer one question: *is jumping traffic in this chair fun?*

In scope:
- Landscape SpriteKit scene. Placeholder shapes for the hero rig (chair, spinning wheels, rider, rockets), vehicles, road and 2 parallax layers.
- Oncoming **compact cars and vans** with the fairness-checked spawner and a speed ramp.
- **Jump** with variable height, coyote time and jump buffer. **Hold for rockets** (air lift and ground boost) with a nitro meter that refills slowly.
- **Safe roof landings.** A front or side hit is a crash: short slow-mo, a tumble, then "Tap to retry" in under 1 s.
- **Score:** distance plus vehicles cleared. **Local best score** is saved.
- **Basic haptics** (3 types).
- **`Tuning.swift` + in-game tuning panel + two control schemes.**
- **Unit tests** for jump reach and spawner fairness.

## 9. Risks and open questions

### Risks
| Risk | Mitigation |
|---|---|
| **AI art tools draw a character slightly differently each time** | Approve the concept sheet first. Use the layered rig with few animations. Give every asset a fixed canvas and anchor. Attach reference images to each issue. Run `check_assets.sh`. |
| **The game isn't fun** | That's exactly what M1 tests. Tuning is cheap (one file plus live sliders). Nothing else gets built until it feels great. |
| **Representation missteps** | Your friend plays the first almost-finished version (M5 beta) and gives honest feedback on the hero, chair, crashes and text before launch. Optionally, also get feedback from the WCMX/adaptive-sports community. Use no real athletes' names. |
| **Claude can't see or feel the game on your phone** | Clear playtest notes, the tuning panel, unit tests for the math, and simulator screenshots Claude takes on the Mac. |
| **Free-account installs expire every 7 days** | Just press Run again until TestFlight is available. |
| **Public repo: people can see and copy the art** | It's still legally yours (all rights reserved). You could make the repo private later, which only affects free CI minutes, and we're not relying on those. |
| **iPad window resizing** (newer iPadOS versions push apps to support resizable windows) | The "design-safe area" layout already adapts to any aspect ratio. We test on your iPad in M1. |
| **Ad and policy rules change** | Check AdMob, ATT and age-rating requirements again at M4 rather than trusting today's details. |
| **Earning very little** | Treat money as a bonus. Keep costs at $99 a year. |
